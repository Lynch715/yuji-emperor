# 正文接口链路审计

日期：2026-11-02。沿用现有Chat Completions协议、预设、思考参数与存档v4，不修改时间制度、数值结算或模型提供商。

## 核对结果与修改

连接测试和正文原本已经共用`callJSON`及内存中的接口配置。区别是连接测试校验`ok/message`，正文要求`chapter`包含朝、午、夜三段，并按引擎结算修正文案。测试只检查表单，不自动保存；试读模式也不会因为连接成功而自动调用付费接口。

确认存在一个空章漏洞：三段均为空字符串，或正文全部被结算校验删除时，原调用仍可能提交一章空正文。现由`src/ui/turn-request.js`统一构造正文请求，在现有结算校验后检查至少一段有可读内容；三段全空会触发原有格式重试，最终失败保留待续回合。合法空槽可略写。接口失败不自动提交试读文案；玩家仍可主动选择“先记入起居注”。

设置新增当前叙事模式说明。试读存档的“保存并用于正文”会先验证并保存当前表单，再启用后续接口叙事，避免使用旧配置；保存失败、连接测试进行中、只读保护或待续回合均不会切换模式。连接成功提示明确要求保存设置。已有接口存档继续使用“保存设置”，无需新开一局。

重试预算维持DESIGN原规则：每回合最多4次、总计240秒，连接测试使用独立预算。手动重试在尚有预算时复用已保存的预演，刷新不会补充次数或重掷；预算耗尽后可主动按原结算入注，没有无限重发。

## 自动回归

新增11项生产调用链测试，总计**136项通过，0失败、0跳过**。

- DeepSeek思考开 / 关、千问思考开 / 关、自定义接口：先调用连接测试，再以相同配置调用真实正文请求函数；检查地址、鉴权、型号、流式与JSON参数，以及排程 / 天命 / 结算提示词。正文流按UTF-8分块，忽略思考内容。
- 真实核心提交和存档封装回读：章节一致、只推进一次、提交幂等；模型反应仍经原结算校验。
- 空白 / 校验后全空、错误结构、断流、长度截断：均纳入原预算重试，完整正文才允许提交。
- HTTP401不自动重试；读档后修正配置，沿用原预演和剩余预算完成同一回合。
- 连续四次无效回复、过期预算、缺少密钥：不提交、不重掷，不发出超限或无密钥请求。
- 兼容服务商返回非流式JSON包装的正文。
