## 第一部分　推演为什么慢、怎么改

### 现状：一旬要串行走多少次模型

`advance()`（src/ui/app.js）里一旬的请求链是**严格串行**的：

1. `classifyMemorialSchedule` —— 每一本带朱批的奏折**各发一次**分类请求，`for` 循环里逐个 `await`。批了 4 本就是 4 次往返。
2. `requestScheduleIntents` —— 口谕/自拟情节意图解析，再一次。
3. `requestTurnNarrative` —— 主叙事。一次要同时产出：朝/午/夜三段正文 + **每本新奏折 160–260 字** + reactions + sceneMemories + ambitionEvidence + factUpdates + rumors + hook。输出 token 是耗时的大头（中文约 1 字 ≈ 1 token，3 段 + 4 本奏折轻松 2500–4000 token）。
4. `inspectNarrative` 发现违规 → `rewriteMessages` 再发一次改写。
5. `validateTurnNarrative` 仍不过 → **整段重来**（最多 4 次、240 秒预算）。

另外：输入里每旬都带完整 `dynastyBible`（25 位官员带性格）、前尘、格局、结算表、新奏报，首 token 等待也长。

其他游戏通常是「一次请求、纯文本、短输出、不校验」，所以快。这个游戏慢不是模型问题，是**请求次数 × 输出长度 × 校验重试**叠出来的。

### 先测再改

浏览器控制台执行：
```js
JSON.parse(localStorage['yuji:metrics']).slice(-20).map(m=>[m.attempt,m.result,(m.durationMs/1000).toFixed(1)+'s',m.inputTokens,m.outputTokens,m.cachedTokens])
```
看一旬里有几条记录、哪条最长、`attempt` 是否经常 >1（说明在重试）。同时确认设置里「深度思考」没开（开了 max_tokens 16000，会慢数倍）。

### 改法（按收益排序）

**P1　把预处理合并成一次，并且能跳就跳**
- 朱批分类并进意图解析：`intentMessages` 的输入本来就含 `:remark:` 条目，让它同时返回 `remarkKind`，删掉逐本的 `classifyMessages(text,'remark')` 循环。
- 没有任何自由文本（无下旨、无自拟、无朱批）时，不发意图请求（现在已 `if(!inputs.length)return []`，确认朱批也走这条）。
- 朱批先用本地规则（engine 已有 negation-aware fallback）判，规则能确定的不问模型。

**P2　奏折正文从主叙事里拆出去，并行生成**
- 主叙事只写三段正文 + summary + hook + reactions 等短字段。
- 新奏折正文用独立请求 `memorialMessages(state, forecast.newMemorials)`，与主叙事 `Promise.all` 并行；耗时变成两者取最大值而不是相加。
- 更进一步：奏折正文在玩家**打开奏折时**才懒加载，未加载前先显示 `memorial-templates.js` 的模板文本。玩家点「下一旬」后等待的只有正文。
- 奏折请求失败不阻塞回合，保留模板文本，可单独重试。

**P3　软违规本地修，不再整段重来**
- `inspectNarrative` 查到的断言违规：优先本地处理（删句或改为“恐”“传闻”句式），不再发改写请求；只有硬错误（JSON 结构缺失、正文为空）才重试。
- 配合自由度三档：最自由档直接跳过断言检查。
- 重试上限改为 2 次，预算 240s → 90s。

**P4　缩短每旬输入与输出**
- 篇幅默认改为「精简」或把「标准」下调到 100–220 字。
- `dynastyBible` 只发本旬出场/被提及的人物全卡，其余只发「id｜名｜职」一行。
- reactions 最多 3 人；factUpdates 最多 3 条；rumors 最多 2 条。
- `流水账` 6 条 → 3 条。

**P5　边写边读（感知速度）**
- 流式解析 JSON 里 `chapter.朝` 的部分字符串，一到就渲染；玩家开始读第一段时后面还在生成。确认 `streamDraft` 已经做到逐段显示，没做到就补上。

预期：一旬从「4–6 次串行请求、40–120 秒」降到「1 次主请求 + 1 次并行奏折、约 15–30 秒」，且读到第一段只需几秒。

## 第二部分　科技与生产线路

### 设计目标
玩家**花钱、派人、花时间**研究 → 解锁**生产线路**（州郡产业）→ 产业让州郡**繁荣**增长 → 繁荣抬高赋税与粮产。经济从“一次性政令加减”变成“可复利的长期发展”。数值全部由引擎结算，模型只写叙事（守住「引擎记账，模型叙事」铁律）。

### 新增状态（save 版本 +1，旧档迁移为全 0）
```js
state.tech = {
  funding: 0,            // 每月拨给格物的经费（万两），从国库月结扣
  current: null,         // { id, progress }  正在研究的条目
  done: [],              // 已完成科技 id
  lead: null,            // 主持官员 id（工部尚书/钦天监等）
};
province.prosperity = 0; // 繁荣 0–100，复利成长的核心
province.industries = []; // [{ type, level, builtTurn }]
```

### 科技树（src/core/tech.js，常量表，约 18 项，5 条线）
| 线 | 示例条目（前置 → 后置） | 效果 |
|---|---|---|
| 农政 | 精耕细作 → 占城稻推广 → 番薯玉米 | 粮产 +10%/+15%/+20%，灾年减损 |
| 水利 | 水车改良 → 束水攻沙 → 漕运疏浚 | 修河费用降低、灾情增长减缓、解锁「漕运」产业 |
| 工商 | 织造改良 → 匠籍松绑 → 银钱折纳 | 解锁织造局/窑场；全国繁荣增速 +；`governance` 小幅变动 |
| 盐铁 | 晒盐法 → 冶铁鼓风 → 新式火器 | 解锁盐场/铁冶；军备 readiness + |
| 海贸 | 宝船图式 → 市舶则例 | 需先「开海」；解锁市舶司；互市收入 × |

每项：`cost`（总经费万两）、`months`（最短月数）、`office`（主持衙门）、`prereq`、`effects`、`unlocks`。

### 研究进度公式（月结中结算）
```
月进度 = min(funding, 上限) × 主持官员能力系数(0.6–1.4) × (0.6 + 吏治×0.004)
         × 派系系数（清流当权且态度不满时 ×0.8，“奇技淫巧”之议）
progress ≥ cost 且已过 months → 完成，写入 done，生成一条结算 note 和一本工部报捷奏折
```
资金有上限（如每月 20 万两）防止一次砸钱秒研究；钱不够时自动按国库余额缩减并记账。

### 生产线路（州郡产业）
| 产业 | 需科技 | 建造 | 产出（季结） | 副作用 |
|---|---|---|---|---|
| 屯田/圩田 | 精耕细作 | 30 万两·3 月 | 粮 + | 无 |
| 织造局 | 织造改良 | 40·4 | 税 +，繁荣 + | 民心小 − (征匠) |
| 窑场 | 匠籍松绑 | 30·3 | 税 + | — |
| 盐场 | 晒盐法 | 35·3 | 国库 + | 吏治压力（盐课贪墨），吏治低时产出打折 |
| 铁冶 | 冶铁鼓风 | 45·4 | 税 +，边军战备 + | 民心 − |
| 漕运 | 漕运疏浚 | 60·5 | 全国粮运损耗 −、繁荣扩散到邻州 | 维护费 |
| 市舶司 | 市舶则例 + 开海 | 50·4 | 互市收入 + | 海防边患 + |

- 建造复用现有 `projects` 在途政务机制（cost、end、province），完成后写入 `province.industries`。
- 每州最多 2–3 个产业槽，可升级到 3 级；每级有季度维护费。
- 产业受灾情、叛乱、民心影响：`provinceTaxFactor` 为 0 的州产业停产。

### 繁荣：经济发展速度的核心
```
每季：prosperity += 基础0.5 + Σ产业贡献 + 科技加成 − 灾情/15 − (民心<30 ? 2 : 0)
      繁荣上限 100，接近上限增速递减（×(1 − prosperity/120)）
赋税：nationQuarter 中 p.tax × (1 + prosperity/100)
粮产：quarterlyGrain 中按州 pop × (1 + prosperity/200) 加权
人口：年结 pop 增长率与繁荣挂钩
```
这样玩家投入越早、维持越稳，后期增长越快；天灾、战乱、苛政会把繁荣打回去。

### 玩家怎么操作
1. **下旨**新增政令类型「格物」「兴业」：意图解析的 edictType 加入 `格物`（设研究方向+经费）、`兴业`（某州建某产业）。自由口谕「命工部研制新式水车，每月拨五万两」解析为 `allocate → tech`。
2. **奏折**：工部/户部每隔若干旬上「请研某法」「某州请设织造局」的奏折，选项即投入方案。
3. **面板**：新增「格物」面板（科技树、当前进度、月经费滑杆）；州郡详情增加「产业」一栏与繁荣值。
4. 自由度三档：最自由档允许玩家口谕提出树外的新发明，引擎映射到最近的一条线并给予该线的通用加成，名字由玩家定。

### 与 LLM 的接口（注意别拖慢推演）
- 【本旬状态】只增加一个短字段：`格物: {在研, 进度百分比, 本旬突破}`，产业只在本旬有建成/停产时才列出。**不要把整棵科技树放进每旬提示**。
- 突破、建成写进结算表 notes，模型照写。

### 平衡参考
当前季度税收约 12 州 × 10 × 0.7 吏治率 × 3 ≈ 250 万两。科技单项 60–300 万两、产业 30–60 万两，大致前期 1–2 年能拿到第一批产业收益，十年级别看到繁荣质变。用 `scripts/simulate.mjs` 加一个「全力格物」策略跑 30 年，对比现有策略。
