# 皇帝推荐、请求精简与国势全览

## 预设开局

七位皇帝各有两项宏愿、两项心事推荐及对应开局理由，数据集中在`src/ui/opening-options.js`，沿用既有目标ID和达成条件，不增设另一套目标判定。

|皇帝|推荐宏愿|推荐心事|
|---|---|---|
|汉武帝|整顿吏治、北伐雪耻|君臣相知、有人承继大统|
|唐太宗|天下归心、北伐雪耻|君臣相知、白头不负故人|
|宋仁宗|整顿吏治、天下归心|安度十载春秋、君臣相知|
|明神宗|整顿吏治、富国安民|君臣相知、儿女绕膝|
|明思宗|整顿吏治、富国安民|君臣相知、有人承继大统|
|清圣祖|天下归心、四夷宾服|安度十载春秋、君臣相知|
|清世宗|整顿吏治、富国安民|有人承继大统、君臣相知|

推荐是根据现有游戏开局设计的玩法建议，不表示皇帝的真实心理，也不预定后续史实。选择预设时自动填入，可自行更换或选随机；同一登基窗口回切皇帝会保留该皇帝的自选目标，回到架空则恢复原有帝名、年号和目标。也可一键重新采用推荐。直接调用`createOpening`时，未传目标或传空数组默认推荐，明确传四个空选项仍随机。

存档仍为v14；旧档的目标、档位、待续、原骰不变。新预设推荐等同于玩家手动选择四项目标，减少原随机选目标的掷骰消耗，故同种子新开局的后续抽签可能与原默认随机目标不同；不是改写旧进度。

## LLM输入

检查后确认原请求已通过`scenarioById`和当前存档取人物、地名及背景，并没有发送七套皇帝资料。此次补上发送到`callJSON`的请求体回归：逐个检查七位皇帝的正文、面谈、意图解析、改写及本纪，其他皇帝、未选文风、推荐清单均不混入，目标只从当前存档取。

正文请求移除面谈任务与格式；面谈请求移除正文、风闻、宏愿证据等无关格式；本纪只用王朝规则和本纪任务。共同的世界规则、人物限制、史实不决定结果和A14要求保留，所有原断言仍运行。缓存验证改为检查共同规则前缀及各自任务隔离，正文连续旬请求公共前缀仍不少于60%，同人面谈仍不少于85%。

同种子崇祯固定样本，按`JSON.stringify(messages).length`比较输入字符（不是服务商token计费）：正文5617→5441，少176字符（3.1%）；面谈3137→2340，少797字符（25.4%）；本纪1908→922，少986字符（51.7%）。未选资料原本未发送，因此不把这些字符变化说成删除整套皇帝库的收益。未调用真实模型API。

## 档位与国势

- 自由度仍用`free / mid / real`，显示名改为「想做就成 / 多数能成 / 成败看实力」，开局和设置均有解释；难度仍用`easy / normal / hard`，显示为「容易 / 标准 / 困难」。难度说明准确指向圣旨落实，不把它说成改变初始国库、灾难概率或所有掷骰。概率、门槛和存档字段不改。
- 桌面新增国势入口，手机沿用国势按钮。面板含九项总览和变化、俸饷 / 三类积欠 / 粮储月数 / 月季测算、3/12/36旬走势、三币种流水、十二州人口税额民情与驻军、京营四境、各派在任席位、外邦互市与年贡、在途政务、战事和储位。
- 财政测算直接使用纯函数`nationMonth / nationQuarter`，不推进时间、不掷骰、不保存。显示当前条件下的估算，季度总收入和补欠后净入库分开；固定俸饷可付月数不冒充全部财政用度。
- 趋势从实际账目反推，跨原有历史分卷；只画能从当前往回连续核对的旬次，不填补缺失历史。面谈等当旬已办变化单独计入流水，不重复算入已完成旬的走势。流水包含库间调拨，明确显示入、出和净变。
- 密集数字使用等宽数字排版、警示标记、趋势图和数据表；360px表格转为双列数据卡片，无页面横向滚动。缺钱、缺粮、空历史均有空态，不出现NaN或虚构曲线。图片、档案和原有游戏规则沿用。

## 验证

新增8项测试，覆盖全部推荐 / 自选 / 旧档、35组实际请求体隔离、任务分流、档位ID与门槛、权威结算与只读性、跨分卷真实走势 / 断档 / 面谈去重、流水币种 / 空态 / 转义。全套387项通过；200年、7,200旬模拟结果与上一版完全相同。

应用内浏览器验证崇祯推荐填入 / 自选回切 / 架空恢复、空卷试读开局、三旬实际推进、旧v14读取、国势时段切换及360px无横向滚动；具体截图与验证结果随发布核对。构建约587KB，上限580KB调为600KB，图标预算不变，无新增依赖。
