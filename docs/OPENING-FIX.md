# 开局无响应修复记录

日期：2026-11-02。用户截图中勾选试读，并反馈点击“承天践祚”后按钮无变化、无提示。截图没有设备日志或浏览器版本，无法单凭图片确定设备根因。

## 已确认的缺陷

原表单在try之前直接调用`crypto.randomUUID()`。该方法不可用或调用被拒绝时，async提交处理器立即拒绝，没有进入任何错误提示或按钮恢复流程。连接测试不使用这一步，因此连接测试能成功而开局仍可失败。

在独立localhost页面中，仅注入“randomUUID不可用”的故障，未改动游戏提交代码。原版点击后出现`TypeError: crypto.randomUUID is not a function`，表单停留、按钮不变、原错误提示为空，与用户描述的表现一致。此处证明的是一种可复现的代码缺陷，没有把它宣称为已取得用户手机证据的根因。正常核心开局用1,000个固定种子检查，未发现默认试读规则自身报错。

另发现开局错误原本用原生dialog之外的toast显示，不能可靠呈现在弹窗前；空白卷写入失败也可能在激活内存中的新局、关闭表单后才返回失败。

## 修改

- `src/ui/new-game.js`负责开局种子和准备流程。优先保留原UUID方法；缺失 / 抛错时尝试随机字节，再回退到时间与页内递增序号。这只是开局seed，不能用于密钥或认证；所有游戏掷骰仍由core/rng.js按seed进行。
- 读取表单、准备seed和创建世界均放进错误处理。中文准备 / 保存提示与错误在登基弹窗内显示，不依赖背景toast；无效姓名、年号或接口配置会明确提示。
- 提交期间禁用表单、防止重复提交。关闭正在铸世的窗口会中止接口请求；上一层菜单延迟到达的close仍按当前表单归属过滤。
- 正在写入存档时阻止关闭与Esc。新卷成功写入后，才替换当前内存状态与活动卷位；失败保留当前卷、表单和可重试按钮。已有卷位仍先按原store.archiveAndSave封存，不改存储规则。
- 试读完全离线，不因已有接口配置而发送请求。接口模式仍使用原提供商参数、世界校验与请求预算。
