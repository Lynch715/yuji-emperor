## 1. UI、操作逻辑与手机端

### 跟手（P0）

**U1　全局非被动触摸监听拖慢滚动**
`src/ui/mobile.js` 在 `document` 上以 `{passive:false}` 监听 `touchstart`、`touchmove`。浏览器每次滑动都必须先跑完这个函数才能开始滚动，低端安卓上会明显发黏。
改法：删除 `touchstart/touchmove` 监听，只保留 iOS 的 `gesturestart/gesturechange`。`style.css:2121` 已有 `touch-action: pan-x pan-y`，足以挡双指缩放。

**U2　没有按压反馈，hover 在手机上“粘住”**
全部 CSS 只有 `:hover`，没有 `:active`，也几乎没有 transition。手机点按无即时反馈，点完后 hover 底色还残留在按钮上。
改法：
- 所有 `:hover` 包进 `@media (hover:hover)`；
- 按钮、奏折卡、时段卡加 `:active { transform: scale(.97); background: var(--panel-active) }`，配 80ms transition；
- `-webkit-tap-highlight-color: transparent`。

**U3　整页重绘**
`app.js:76` 的 `render()` 每次都执行 `#app.innerHTML = renderApp(...)`，只恢复 `window.scrollY`。手机布局下 `#app` 固定为 `--app-height`，真正滚动的是正文、抽屉等内部容器，它们的滚动位置和输入焦点每次都会丢。
改法（由轻到重）：
- 至少给可滚动容器加 `data-scroll-key`，重绘前记下 `scrollTop`、`activeElement` 的 id，重绘后恢复；
- 更好的是拆成 topbar / schedule / memorials / drawer 四个区域分别渲染，只更新变化的区域。

**U4　流式正文 O(n²)**
`onPartial` 每来一个分片，都对全文重跑一次 `extractPartialChapter`，再整体写 `textContent`。改为 `requestAnimationFrame` 节流（每帧最多一次），并且只在原文长度变化时重算。

**U5　visualViewport 滚动时每帧写 CSS 变量**
`visualViewport` 的 `scroll` 事件每触发一次就写一次 `--app-height` 和 `--viewport-top`，都会引起全局样式重算。改为 rAF 合并；值没变时不写。

### 操作逻辑（P1）

**U6　没有返回手势管理**
全局没有 `pushState` 或 `popstate`。新版安卓 Chrome 的返回键能关掉 `<dialog>`，但 iOS 侧滑返回和旧浏览器会直接离开页面，玩家以为退出了游戏。
改法：打开弹窗时 `history.pushState({modal:1})`，在 `popstate` 里关闭弹窗；起驾或续写进行中时，加 `beforeunload` 提示。

**L1　奏报有两条处理通路**
“上朝（最多 3 本）”和“批折（每 3 本 1 点精力）”都能处理奏报，界面上看不出两者的区别。
建议：在行动选择处并列说明。例如上朝会触发廷议和派系表态，批折更省精力。或者合并为一个“处理奏报”入口，再选方式。

**L2　批折劳动量大**
每旬 3–6 本，每本都要选项加批语；一局动辄上千旬，后期会变成机械操作。建议：
- 每本给“依票拟”（内阁或首辅的默认建议，并显示首辅派系倾向），一键采纳；
- “例行奏报全部照准”的批量按钮；急报永远置顶，不允许批量处理；
- 手机上可以加滑动手势：右滑照准、左滑留中。

**L3　排程层级深**
现在是先点空时段，再选行动，再选对象。建议：
- 空时段下直接放 2–3 个常用行动快捷标签；
- 加一个“沿用上旬日程”按钮。

**L4　禁止缩放影响可访问性**
`user-scalable=no` 加上 JS 拦截双指，长篇中文正文无法放大。若坚持禁止缩放，需在设置里提供字号三档（正文 16/18/20px）。

## 2. 冲突

### 2.1 引擎 × LLM

**C1（P0）校验器把正常叙事整句删除——已复现**

把下列 5 句喂给 `validateTurn`，全部被删除：

| 原句 | 删除原因 |
|---|---|
| 某某只说了一两句，便退回班列。 | “一两” 被当成 1 两银子，在结算里找不到依据 |
| 陛下三两步走下丹墀。 | 同上（“三两”） |
| 先帝驾崩那年，某某年方二十。 | 追忆被当作本旬死亡断言；“年方二十”没有年龄依据 |
| 北狄屡屡入寇，边民苦之。 | 背景描写被当作本旬战果 |
| 某某自出任户部以来，夙夜在公。 | 履历被当作本旬任免 |

实测结果：“午”段被整段删空。按 `turn-request.js` 的逻辑，三段全空会判为失败，并消耗每旬 4 次重试预算。也就是说，一章写得好的叙事反而会被打回重来。

改法：
1. 数字正则加量词白名单：两句、两步、两声、两眼、两行（泪）、两旁、两侧、两人（无“兵、军”时）等。只有“两”后紧跟“银、万两”，或句中出现钱粮语境时，才按金额处理。
2. 断言词加时态豁免。前 18 字内出现以下任一词时跳过检查：曾、昔、当年、旧日、先帝、自…以来、已故、屡屡、每每、素来。“入寇”另需句中没有“屡、常、时有”。
3. 在提示词里明确告诉模型规则：“死亡、怀孕、生产、任免、战果、执行度只在结算表列出时才可写成本旬发生；其余只能作回忆或传闻，并用‘曾、昔’标明。”预防比事后删除便宜得多。
4. 删除后若某段少于 40 字，用试读文案补足，而不是留空，避免触发重试。

**C2（P1）人物反应：输出模板与采纳范围不一致**
提示词让模型按“名册全名”给反应，名册里包含妃嫔、皇嗣、外邦君主。但 `validateTurn` 和 `commitTurn` 只采纳官员，其余全部丢弃，并写入 fixNotes。
二选一：
- 提示词改为“仅限官员”；
- 或者让引擎也接收妃嫔 favor、外邦 attitude，同样限额 ±5。

另外建议加一条约束：每旬所有反应的绝对值总和不超过 10，且只能给本章出现过的人。模型普遍偏向写正面反应，长期会造成好感通胀。

**C3（P1）宏愿证据和长期事实没有字段定义**
输出模板只写了 `"ambitionEvidence":[]` 和 `"factUpdates":[]`。但校验要求的字段分别是 `{id, objectiveId, evidence}`（evidence 还必须包含该目标的全部 keywords），以及 `{subject, key, value, reason}`。模型无从得知这些字段，剧情类宏愿实际上几乎不可能达成。
改法：
- 模板写全字段；
- “宏愿”上下文只发未完成的 story 目标的 `id/objectiveId/keywords`；
- 注意风险：把 keywords 发给模型后，模型可能硬塞关键词来刷完成度。建议再加一个条件：本旬结算中要有相关行动（例如目标是“立储”，本旬必须有立储类排程）。

**C4（P2）面谈提示词要求的字段都被丢弃**
面谈要求模型输出 `favor / effects / revealSecret / endTalk`，`validateTalk` 一概不用。这些字段既浪费输出 token，也让模型误以为自己能控制结局。删掉它们，只留 `reply / innerThought / mood / summary`。

**C5（P2）铸世提示词自相矛盾**
同一条提示词既要求输出 `"era":"年号"`，又说“不得更动玩家名与年号”。从模板中删掉 era。

**C6（P1）世界观写死**
`worldRules` 固定写着“架空王朝、制度近似明清”，官职名 `POST_NAMES` 也是明清体系。这与第 5 节的历史剧本直接冲突，见 5.3。

**C7（P0）结算表原样发给模型**
第 181 旬（三时段都歇息）的 user 消息共 17,815 字，其中结算表 `entries` 占 12,227 字（93 条）。条目里有未取整的浮点，如 `41.10479922420692`，还有大量 `-0.01` 的微小账目。提示词本身又说“正文只写故事，不抄结算条目”。
改法：发给模型前先聚合：
- 同一 path 的 delta 求和；
- 丢弃绝对值小于 1 的项；
- 取整，并把 path 翻译成中文（如 `province.z0.morale` → 湖广民心）。

预计可缩到 1–2k 字，输入成本约减半，叙事也更聚焦。

### 2.2 引擎内部（本轮新增）
- **两条奏报通路的规则差异**（L1）：在引擎中写成显式表，UI 直接读这张表，避免以后两边规则漂移。
- **数字证据和状态精度不一致**：`numericEvidence` 用 `x*10000` 生成合法数字集合，状态里的浮点（例如 0.3 万两 → 3000.0000001）可能匹配不上模型写的整数。建议把合法集合取整到最小记账单位。

## 3. 缓存命中：调整顺序

### 3.1 现状（实测）
- 连续 60 旬，相邻两次正文请求的平均公共前缀为 **1,928 字 / 16,615 字 ≈ 12%**。
- 稳定部分只有 system（238 字）和 user 开头的指令（约 358 字）。紧接着的【状态】JSON 第一项就是带“好感”的人物名册，之后是每旬都变的国势浮点。
- 百炼隐式缓存要求公共前缀至少约 1024 token，命中部分多数模型按输入单价的 20% 计费；显式缓存（`cache_control`）命中按 10% 计费，有效期 5 分钟，每次命中后重新计时，单次请求最多 4 个标记（[阿里云文档](https://help.aliyun.com/zh/model-studio/context-cache)）。按现在的结构，基本达不到命中门槛。DeepSeek 也是按前缀自动缓存，原理相同。

### 3.2 目标顺序：从稳定到易变

```
[system]  L0 规则层（所有调用共用，整局几乎不变）
          · 铁律、称谓、禁写、文风规则+范文、受限断言词说明
          · 各类调用的输出模板（正文 / 面谈 / 分类 / 立传）
          · 目标 ≥1200 token，让面谈、分类、立传也能命中同一前缀
[user#1]  L1 王朝设定集（开局生成，任免/死亡/册封时才重建）
          · 王朝背景、派系定义（名称+诉求，不含势力数值）
          · 人物静态卡：id｜名｜职位｜派系｜性格｜出身（按 id 排序，不含好感）
          · 州郡名与描述、外邦静态卡
[user#1]  L2 只追加的历史
          · 前尘：卷摘要（只追加，不做滑窗）
          · 长期事实：改为只追加；满 30 条时整批封存成一条摘要，
            不再用 slice(-30)（滑窗每新增一条就让后面全部失效）
          ← 显式缓存标记放这里（千问可用 cache_control）
[user#2]  L3 本旬动态（每旬必变，放最后）
          · 数值表：好感、国势、州民心、派系势力（取整）
          · 流水账（最近 6 旬）、在途政务、本旬前后变化
          · 玩家排程、聚合后的结算表、廷议、新奏报
          · 本旬任务指令（“把本旬写成朝午夜三段……”）
```

要点：
1. 本旬任务指令移到 L0；动态数值和静态资料拆开。名册不再夹带好感，好感单独放进 L3 的数值表。
2. `JSON.stringify` 的键顺序要固定：先排序再序列化。L1/L2 里不放 turn、日期这类每旬变化的字段。
3. **面谈改为真正的多轮消息**：`[L0][L1 + 人物卡][user/assistant 交替的对话][最后一条 user：本句 + 引擎判定]`。现在用 `log.slice(-6)` 滑窗，并把整段对话塞进一个 JSON，每说一句前缀就全部失效。面谈时连发多句，正好落在 5 分钟有效期内，改完后命中率最高。
4. 口谕分类、立传也以 L0 开头，共享同一缓存。
5. 指标：`onMetric` 增加记录 `usage.prompt_tokens_details.cached_tokens`（千问 / OpenAI 兼容格式）和 `prompt_cache_hit_tokens`（DeepSeek），在设置页的请求统计里显示命中率。
6. 回归测试（沿用先红后绿）：连续两旬的正文请求，公共前缀须不少于总长的 60%；相邻两句面谈请求，公共前缀须不少于 85%。

## 4. 文风

现有 6 种：庙堂、冷峻、宫闱、野史、简古、温润。建议拆成三个独立选项，并为每种文风配 80–150 字的范文（放进 L0，既提升质量，也延长可缓存前缀）。

**文风（新增 8 种）**

| 键 | 名称 | 规则要点 |
|---|---|---|
| chapter | 章回 | 说书人口吻，“话说”起、“且听下回”收，段末留悬念 |
| annals | 正史 | 编年纪事体，冷静记事，段末可加一句“史臣曰” |
| intrigue | 权谋 | 重算计与暗线，对话多机锋，每段至少一处伏笔 |
| harem | 宫斗 | 细写位分、眼色、赏赐与站队，杀机藏于礼数 |
| strange | 志怪 | 天象、谶纬、异兆入叙事，但不改引擎结果 |
| gazette | 邸报 | 公文体，条陈式短段，“奉旨”“着即”等官腔 |
| farce | 戏说 | 诙谐轻快，允许温和的喜剧化，不用网络流行语 |
| frontier | 边塞 | 苍凉开阔，写风物与兵民，适合亲征和出巡 |

**篇幅**：精简（每段 80–150 字）/ 标准（120–300）/ 详尽（250–500）。直接改变 user 指令里的字数，同时影响 max_tokens 和费用，设置页应写明。

**视角**：第三人称（默认）/ 第二人称（“你”）/ 史官口吻。

注意：`worldRules` 里“禁用现代词”对戏说同样适用；章回体的“且听下回分解”不会触发校验，无需改校验器。

## 5. 历史帝王剧本

### 5.1 选人原则
优先选开局局面能直接用上现有引擎机制的皇帝：幼帝摄政、权臣、派系、外戚、立储、边患、天灾。这样写剧本就是在填数据，不需要另造系统。

### 5.2 推荐 7 个剧本

| 剧本 | 开局 | 难度 | 用上的机制 |
|---|---|---|---|
| 汉武帝 刘彻 | 建元元年（前 140），16 岁 | 中 | 太皇太后窦氏掣肘、黄老与儒生派系、匈奴边患 |
| 唐太宗 李世民 | 武德九年（626），玄武门之变后 | 中 | 秦王府与东宫旧臣两派、开局即遇颉利南下渭水 |
| 宋仁宗 赵祯 | 乾兴元年（1022），13 岁 | 易 | 刘太后垂帘（摄政）、生母之谜（秘密）、辽与西夏 |
| 明神宗 朱翊钧 | 隆庆六年（1572），10 岁 | 中 | 张居正权臣加摄政、考成法与一条鞭、国本之争（立储） |
| 明思宗 朱由检 | 天启七年（1627），17 岁 | 难 | 阉党权臣、后金、陕西饥荒、低国库开局 |
| 清圣祖 玄烨 | 顺治十八年（1661），8 岁 | 中 | 四辅臣（鳌拜为权臣）、孝庄太皇太后、三藩与台湾 |
| 清世宗 胤禛 | 康熙六十一年（1722），45 岁 | 中 | 夺嫡余党派系、年羹尧与年贵妃的外戚链、秘密立储 |

**每个剧本的核心人物**（其余官员由铸世补足，补足者不得冒用历史名人）：

- **汉武帝**：窦婴（丞相）、田蚡（太尉，外戚）、赵绾（御史大夫）、王臧（郎中令）、董仲舒、汲黯、韩安国、李广；卫青初为平阳公主家奴，作为待遇见人物；太皇太后窦氏、王太后。
  后宫：陈皇后（阿娇）；卫子夫作为首届选妃候选。外邦：匈奴（军臣单于）、南越（赵佗）、闽越、东瓯、西域诸国。
- **唐太宗**：长孙无忌、房玄龄、杜如晦、魏征、王珪、萧瑀、封德彝、李靖、尉迟敬德、李勣。

### 5.3 引擎需要的改动
1. **剧本数据格式** `src/scenarios/*.json`：`emperor`（名、年龄、五才、性格）、`era`（年号、元年对应公元）、`dynasty`、`surname`、`posts`（本朝官职名映射）、`provinces`（12 槽对应历史政区标签）、`factions`、`officials`（含 secret、初始好感与派系）、`consorts`、`children`、`dowagers`、`foreign`、`regency`、`strongman`、`openingThreads`（开局事件，如渭水之盟、鳌拜专权）。
2. **官职名按朝代映射**：汉为丞相、太尉、御史大夫；唐为中书令、侍中、尚书仆射；宋为同平章事、枢密使；明清沿用现有体系。引擎内部仍用同一组职位 id，只换显示名。
3. **世界观提示词可替换**：`worldRules` 去掉“架空、近似明清”的写死文字，改为读取剧本。加一条：“史实只用于人物性格和背景；本局自开局起已偏离史实，生死、成败一律以引擎为准，不得按史实预言或补写结局。”
4. **校验器**：配合 C1 的时态豁免，允许“先帝”“高祖”等追忆。剧本人物的姓名不参与秀女、科举的去重，同时禁止生成器产出这些名字。
5. **史实锚点（可选开关）**：“演义模式”下，历史大事以概率事件出现（如前 129 年匈奴入塞），玩家可以改写结局；“架空模式”完全不出现。
6. **开局界面**：剧本卡片（画像用首字印章，与现有 portrait 风格一致）、一句话局势、难度、核心人物 6 人预览，另保留“自拟王朝”入口。

建议先做唐太宗剧本打通全流程：人物资料充足，开局就有颉利南下这一戏剧事件，难度适中。

## 6. 其他提升乐趣的建议

按投入产出排序：

1. **时间粒度与自动理政**：一位皇帝在位数十年就是上千旬，玩家和 API 费用都撑不住。建议加“委政内阁，快进 N 旬”：引擎照常结算，内阁依票拟处理奏报，模型只写一段合并纪要。只在大事（急报、生死、战事、宏愿节点）时停下交还玩家。
2. **章末悬念**：输出模板加 `hook` 字段（30 字内，写一个下旬可能发生的事），从引擎已生成、尚未发生的线程中挑选，不编造。用来拉动下一旬。
3. **廷议可介入**：廷议名单已有立场，可让玩家在两派之间当场裁断，派系好感立即结算。现在廷议只是旁白。
4. **起居注与史书分离**：在位时看起居注；驾崩后史官据皇威、派系、杀戮记录写本纪，可出现“曲笔”。皇帝会在意身后名，宏愿系统可以接上。
5. **人物关系图**：殿阁里加一张派系、姻亲、师生、仇怨的关系网，面谈和宫斗的目标更直观。
6. **分享卡**：封卷时生成竖版本纪卡（谥号、庙号、在位年数、三件大事、史臣曰一句），复用现有海报样式，带二维码。
7. **收集与周目**：谥号图鉴、结局图鉴、剧本成就（如“贞观之治”“避免土木之变”），跨存档保存。
8. **密折与耳目**：低成本的私下行事，用来获取官员秘密的线索。秘密目前只有面谈试探一条路。
