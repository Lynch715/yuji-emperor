# 御极 · 全面审计与修改单（交 Codex 执行）

日期：2026-11-02　审计对象：本地仓库 `皇帝模拟器`（HEAD `fe84b59`，版本 0.9.1，存档 v4）

## 0. 审计范围与结论

**范围**：通读 `src/core`（19 个文件）、`src/llm`、`src/store`，以及 `src/ui` 中回合流程、面谈、开局、设置和渲染相关代码；对照 `DESIGN.md` 与 `AGENTS.md`。在 Node 22 下跑 `npm test`，结果 **154/154 通过**。另写了 6 个复现脚本，直接调用 core 和 llm 的函数核实下列问题。所有带「已复现」标记的条目都有实测输出。

**结论**：工程底座扎实，回合事务、幂等提交、存档保护、叙事校验和测试都写得认真。主要问题不在这些地方，而在四处：
1. 有一个会让正文**永远生成不了**的预算 bug，另有一个会让中国大陆用户**首屏长时间白屏**的字体加载问题。
2. **数值没有压力**：每旬只“上朝、准奏前三本”，1 年民心 100，3 年吏治和圣德 100，此后 30 年不动。玩家一旦摸到这套打法，整局就没有决策了。
3. 多处随机或选取逻辑实际上是**确定性的**：天灾只落在 4 个州，每届秀女名单完全相同，例行奏报只有 6 个固定标题。
4. 长局**存档体积**会超过 localStorage 上限；每次点按都要序列化整份状态。

**给 Codex 的总规则**（每批次都适用）：
- 遵守 `AGENTS.md` 的硬性原则。凡改数值，都在 PR 说明里写偏离 `DESIGN.md` 的理由。
- 状态结构有改动就把 `VERSION` 升到 **5**，在 `migrate()` 里补字段。旧预演（`pending.forecast`）不重掷、不重算。
- 每个修复都要附一条回归测试，测试名带条目编号，例如 `A1 面谈后超过 240 秒仍可请求正文`。
- 每批次结束跑 `npm test`、`npm run simulate`、`npm run balance`，并更新 `CHANGELOG.md` 和 `docs/ACCEPTANCE.md`。
- 按第 6 节的批次顺序推进，一批一个 PR，不要把不同批次混在一起。

## 1. P0：必须先修

### A1　请求预算跨回合过期，导致正文永远无法生成（已复现）
- **位置**：`src/ui/app.js` 的 `budget()`（约 113 行）、`advance()`（约 372 行），`src/llm/client.js` 的 `createBudget` / `callJSON`。
- **问题**：面谈（`startTalk`）或口谕分类第一次调用接口时，会创建 `state.turnBudget`，`deadline` 是绝对时间（当时起算 +240 秒），而且存进了存档。玩家面谈后排程超过 4 分钟再点“起驾”，`advance()` 会复用这个已过期的预算，`callJSON` 的 `while (now() < deadline)` 一次都不进，直接抛出“本回合请求预算已用完”。之后“重试本旬叙事”永远失败，只能选“先记入起居注”。刷新页面也一样，因为 deadline 已经持久化。面谈三轮再加一次分类，就占满 4 次额度，正文同样无法请求。
- **复现**：`createBudget(t)`，`used=1`，把时钟推进 300 秒后调用 `callJSON`，结果 fetch 0 次，直接抛出预算用完。
- **修改**：
  1. 预算分成两类。**面谈和口谕分类**每次调用新建独立预算，不写入 `state.turnBudget`。**正文预算**在 `advance()` 生成 `pending` 时新建。
  2. 正文预算里只把“已用次数”持久化。240 秒计时从本次 `advance()` 实际发起请求开始算，页面重载后重新起算，不能沿用绝对时间。
  3. “不重掷”的保证来自 `pending.forecast`，和预算无关，这一点保持不变。
- **测试**：①面谈后时钟推进 10 分钟，正文仍能请求；②面谈三轮后正文仍有 4 次额度；③pending 重载后 `used` 保留、时钟重置；④同一 pending 重试时 forecast 的哈希不变。

### A2　Google Fonts 阻塞渲染，中国大陆用户首屏白屏
- **位置**：`src/ui/shell.html` 第 9–11 行，`<link rel="stylesheet" href="https://fonts.googleapis.com/...">`。
- **问题**：同步样式表会阻塞首次渲染。目标用户主要用 DeepSeek 或千问，多在大陆，fonts.googleapis.com 在大陆常被阻断，浏览器要等到连接超时（常见 10–75 秒）才渲染。README 写的“加载失败退回系统字体”只对字体文件成立，对这个样式表不成立。
- **修改**：改成非阻塞加载：`<link rel="preload" as="style" href="…" onload="this.rel='stylesheet'">`，再加 `<noscript>` 回退；或者用 `media="print" onload="this.media='all'"`。去掉对 googleapis 的 `preconnect`，或只保留 gstatic。更好的做法是只为 Ma Shan Zheng 做“御批/急印”常用字子集并内联（几 KB），正文直接用系统宋体或黑体。
- **测试**：`test/ui-audit.test.js` 增加断言，构建产物 `<head>` 里不得有指向外域的同步 `rel="stylesheet"`。用 Playwright 拦截 fonts.googleapis.com 并让请求挂起，`#app` 应在 2 秒内渲染。

## 2. P1：确定性逻辑错误

### B1　天灾只落在 4 个州，例行“请赈”也只来自另外 4 个州（已复现）
- **位置**：`events.js` 的 `eventsMonth` 用 `provinces[s.turn % 12]`；`seedMemorials` 用 `provinces[(s.turn*3+i) % 12]`。
- **问题**：月结只在 `turn % 3 === 0` 时运行，所以 `turn % 12` 只可能是 {0,3,6,9}。实测 40 年里天灾全部落在直隶、湖广、陕西、广东；例行“请赈”全部来自江南、山西、福建、辽东，而且和这些州有没有灾无关。
- **修改**：用 `roll` 抽州，权重为 `1 + 季节系数 + 人口/100`，同季同州不重复。“请赈”奏报只从 `disaster > 0` 的州生成，没有灾州就换成别的例行模板（见 D1）。
- **测试**：固定种子跑 50 年，12 个州每州至少出现 1 次天灾；“请赈”奏报涉及的州，奏报生成时 `disaster > 0`。

### B2　例行奏报署名与职务、议题无关，可能由已故、下狱、外任官员上奏
- **位置**：`seedMemorials` 用 `officials[(turn+i) % officials.length]`，`officials` 包含已故者。这也是 `docs/NEXT-STAGE.md` 第 1 项。
- **修改**：新增 `pickMemorialist(state, type, provinceId)`。请赈、钱粮由该州巡抚或户部官员上奏；军粮由兵部或对应边镇上奏；言官类由左都御史上奏。候选必须满足 `inCapital` 或是该州地方官，并且在任、在世、未下狱。职位空缺时按衙门兜底，再兜底为“通政司”。`courtDebate` 和 `remark` 也统一走 `id`，不再按 `name` 查人。
- **测试**：200 年模拟中，所有新奏报的 `fromId` 都指向当时在世、在任、未下狱的官员，或为“通政司”。

### B3　每届秀女名单完全相同，会出现重名妃嫔（已复现）
- **位置**：`harem.js` 的 `generateCandidates`，姓名、相貌、野心都按下标 `i` 写死。
- **复现**：第 1 年和第 4 年候选名单相同，都是“顾静姝、谢疏影、方明漪……”。
- **修改**：用 `roll` 从姓氏池和名字池抽取，相貌、性情、野心、心机、家世派系都随机。新增全局 `uniqueName(state, pool)`，检查所有在世人物（官员、妃嫔、皇嗣、宗室女），不允许重名。

### B4　皇嗣和旁支姓氏写死为“萧”；科举到第 37 人开始重名；皇嗣名字带数字
- **位置**：`haremMonth` 写死 `"萧"+…+(index>9?index:"")`；`succession.js` 写死 `"萧承"+number`；`courtYear` 科举名为 12 个姓 × 3 个名。
- **问题**：玩家把皇帝名改成“朱厚照”，皇子仍叫“萧景宁”；第 11 个孩子叫“萧景和11”；第 13 届科举开始与早期官员同名，按名字查找的逻辑（朱批、反应、校验）会串人。
- **修改**：`state.imperialSurname` 在开局时取皇帝名首字（存档 v5 迁移时，从 `emperor.name[0]` 或 `reign` 记录补上）。皇嗣按“字辈 + 单字池”生成，用 B3 的 `uniqueName` 去重。科举改用随机姓名池。

### B5　婴儿继位：0 岁天子五才 60–80，即位当旬配 22 岁皇后（已复现）
- **位置**：`succession.js` 的 `succeedEmperor`。
- **修改**：
  1. 新帝未满 16 岁时进入 `state.regency = { regentId, until }`。摄政从太后、内阁首辅、宗人令中选权谋最高者。
  2. 摄政期间 `proxyMemorial` 每旬代批 1–2 本；玩家只能排程批折、召见、经筵（可作为私下行事的变体）、歇息。
  3. 五才 = `aptitude × min(1, 年龄/16)` + 教养加成，亲政时再定型。
  4. 不在即位时生成后宫。年满 16 岁触发“大婚”事件生成后宫。
  5. 迁移：旧档已有幼帝的，补上 `regency`。
- **测试**：0 岁储君继位后，`regency` 存在，后宫无新妃；第 16 年亲政事件触发。

### B6　宏愿“在位年数”用全局旬数，继位者一即位就达成（已复现）
- **位置**：`ambitions.js` 的 `goalMetric`：`reignYears: s.turn/36`；`children`、`maxFavor` 也跨朝累计。
- **复现**：第 400 旬继位的新帝，“安度十载春秋”的“在位年数”立刻显示 11.1 并判定达成。
- **修改**：`reignYears = (turn − reign.accessionTurn)/36`；`children` 只计 `fatherId === reignId(s)`；`maxFavor` 只计本朝未退居的妃嫔。继位时新帝重掷宏愿和心事，旧条目连同达成状态存入该朝的 `chronicles` 记录。达成凭据的 receipt 改为 `goal:<reignId>:<id>`。

### B7　圣旨被封驳仍扣全额钱粮；同类圣旨可每旬重复刷；“减赋”不减赋（已复现）
- **位置**：`edicts.js` 的 `issueEdict`、`EDICTS`。
- **复现**：修河被封驳（执行分 −6），国库照扣 60，不生成工程。
- **修改**：
  1. 封驳（tier 4）时钱粮退回，起居注写明“内阁封还”，皇威 −3 保留。阳奉阴违照扣全额，按 30% 兑现，另记一条“截留侵吞 X 万两”。
  2. 冷却：同一 `edictType` 有在途工程时不能再下；非赈灾类旨意完成后冷却 6 旬。赈灾按州冷却。
  3. “减赋”给目标州（或全国）设 `taxRelief = { factor: 0.8, untilQuarter }`，由 `nationQuarter` 读取。“加税”设 `taxSurge = { factor: 1.2, untilQuarter }`，持续期间每季民心 −2。现在“加税”是一次性 +40，必须删掉。
  4. 存档 v5 给州补上 `taxRelief/taxSurge` 字段。

### B8　外交状态与战役脱节；边患和外邦无关（已复现一部分）
- **位置**：`foreign.js` 的 `diplomacy` / `foreignMonth` / `advanceCampaigns`。
- **问题**：
  - 交战中做一次“互市”，状态就变成“通好”，战役却还在进行（已复现）。“册封”“索贡”同理。
  - 宣战永远用 `frontiers[0]`（北境）。可以对婚盟国或朝贡国宣战。
  - 边患每月固定 −1..+3，与外邦态度、状态、实力都无关；入寇后重置到 45，所以不管怎么经营外交，四境都会周期性入寇。
  - 战役胜负基本由 `other.power` 决定：实力 40 的国家必胜，实力 90 的必败。
- **修改**：
  1. `foreign[i].frontier` 绑定一个边境方向（v5 迁移时按下标分配；5 国 4 边时，两国可共用一边）。
  2. 交战中只能“议和”和“接见”；对婚盟或朝贡国宣战须二次确认，并有皇威、圣德惩罚。
  3. `foreignMonth`：边患增量 = `基数 + (该方向外邦 power − 本方向军力)/50 − (attitude−50)/25`；婚盟或朝贡时增量减半；可以下降。
  4. 战役加入粮草消耗、`enemyReadiness` 逐旬变化、将领从该边总兵和兵部尚书中取武略较高者。用固定种子的胜率表做验收：同等国力胜率在 40–60% 之间。
  5. 宣战入口检查 `status` 和 `frontier`。

### B11　试读模式下面谈直接泄露人物秘密；面谈失败时丢弃模型台词

### B15　“天命大凶：内库失窃”实际扣的是国库

- **修改**：改扣 `privy`，或把文案改成“户部银库失窃”。按 DESIGN“大凶预先定死一件实损”的要求，建议从 3–4 种实损里随机选一种：国库失窃、边城失守一座（边患 +15）、宠妃小产（若有孕）、圣躬染恙（健康 −8）。

### B16　继位后的纪年、选秀年、科举年基准不一致

## 3. P1：数值与经济平衡

**实测（固定种子 `audit3`，每旬只“上朝·准奏前三本”，其他时辰空着）：**

| 年 | 国库 | 粮储 | 民心 | 吏治 | 圣德 | 皇威 | 心情 |
|---|---|---|---|---|---|---|---|
| 1 | 872 | 849 | **100** | 87 | 94 | 58 | 46 |
| 3 | 1299 | 1247 | 100 | **100** | **100** | 58 | 14 |
| 15 | 1371 | 3636 | 100 | 100 | 100 | 58 | 1 |
| 29 | 1300 | **6424** | 100 | 100 | 100 | **58** | 1 |

六派势力 30 年里同步从 30–49 降到 14–33；在世官员从 25 人增加到 52 人；京营和边军兵力 30 年没有变化。现有的 `npm run balance` 只验收了国库和亡国率，所以没发现这个问题。

### C1　国势满值饱和（核心问题）
- **原因**：例行奏报“准奏”固定给 民心+2、圣德+1、吏治+0.5，没有边际递减，也没有回归；吏治 >60 时民心每月还有 +0.5。全国民心与各州民心脱钩。
- **修改**：
  1. **全国民心 = 各州民心按人口加权的平均值**，不再单独累加。效果包里的 `morale` 改成作用于相关州，或作用于全部州并 ×0.3。
  2. **均值回归**：吏治每月向 `50 + 在任六部履职分 − 贪墨侵耗` 回归 3%；圣德、皇威每月向 50 回归 2%；心情每月向 55 回归 5%，替代现在的“每月 −1”。
  3. **边际递减**：数值 ≥80 后，正向增量 ×0.5；≥90 后 ×0.25。可以放在 `applyEffects` 里统一处理，对 `nation.morale/governance`、`emperor.virtue/prestige` 生效，记账写实际值。
  4. **例行奏报不再白给**：准奏的收益依赖事实。“请赈”只在有灾时出现；“六部请整饬案牍”这类例行准奏只给 +0.1 吏治，驳回不扣民心；真正的收益来自事件奏报和圣旨。
- **新增模拟断言**（加到 `scripts/stage8-1-balance.mjs` 或新建 `scripts/balance-v5.mjs`）：
  - 贪心策略（每旬准奏前三本）：前 20 年里，民心、吏治、圣德任一项 ≥95 的旬数占比 < 15%。
  - 随机策略：四项国势的 20 年标准差都 ≥ 5（不能卡死在边界）。
  - 原有断言保留：纯歇息 15 年内亡国，亡国率 10–35%。

### C2　粮储只增不减（30 年增加 5,600 万石）
- **修改**：季度新粮 = `Σ州(人口×0.15×(1−灾情/100))`；月耗 = 军粮 +（灾情 > 0 的州 × 赈济消耗）；粮仓上限 = `年耗 × 3`，超出的部分每年霉变 10%。粮储低于 1 个月军粮时，边军战力 −30%。

### C3　负数效果在 0 处被静默截断，内帑没有收入
- **位置**：`effects.js` 的 `clamp(old+delta, 0, max)`。
- **问题**：内帑归零后，每月宫用、赏赐类扣款直接“消失”。国库和粮储同理（事件效果包没有可负担性检查，只有奏报准奏检查了国库）。实测内帑 30 年都停在 0。
- **修改**：`applyEffects` 遇到钱粮类负增量、余额不足时，把差额记入 `arrears`（内帑另设 `privyArrears`），由月结优先补付；不能静默抹掉。内帑加入固定收入（皇庄、盐课，每月 +3 左右）。“节俭”标签改成宫用 −30%。

### C4　京营兵力只减不增
- **问题**：边城失守 −12,000，民变逾期 −10,000，没有任何补充渠道，长局最终必然亡国。
- **修改**：“征兵”旨意加一个参数（京营或某边）；京营每月向编制目标（45,000）回补 1%，从国库支付饷银；补充受民心和粮储限制。

### C5　派系势力同步漂移，党争和权臣机制失效
- **位置**：`courtMonth`：所有派系都按 `(50−皇威)×0.006` 变化。
- **修改**：派系势力 = `Σ本派在任官员的 职级权重 × 能力` 归一化，再叠加事件修正；任命、罢免会立即改变势力。权臣条件按 DESIGN 补上“任一官员”分支（野心 × 势力 ×(100−皇威) 超过阈值）。
- **验收**：随机策略 200 年中，权臣代批至少触发一次，且不是每旬都触发。

### C6　皇威常规玩法中不变；心情长期见底
- **修改**：当廷驳回、问责成功、祭天、胜仗、雷厉风行给皇威；被封驳、败仗、代批扣皇威；加上 C1 的回归。郁结（心情 < 20）持续 3 个月以上时，健康每月 −1。

### C7　官员几乎不死、不致仕，人数单调增加
- **位置**：`courtYear` 中 65 岁后每年只扣 3 点健康，约 93 岁才会去世；科举每 3 年加 3 人。
- **修改**：年龄死亡率表（60 岁以上每年 2%，70 岁以上 6%，80 岁以上 15%）；70 岁自动请求致仕（生成奏报，准或留）；科举人数按空缺数决定（1–5 人）。

### C8　宫斗与小产过于稀少，目标是固定的
- **修改**：发起者从“野心 > 50”中按心机加权抽取；目标从与其关系最差的人中抽；小产概率与心机差挂钩（每次事件 2–8%），不再要求 `r.value === 1`。

### C9　宴请、互市性价比失衡

## 5. P3：工程

### E1　存档体积与写入频率（长局必爆 localStorage）
- **实测**：试读文案下，360 旬存档 1.4–2.7 MB，主要是各章 `entries` 台账和 `volumes`。按这个速度，200 年约 30 MB，接入模型正文后更大；localStorage 恢复副本大约在 20–30 年时开始持续写入失败。`arrange()` 每点一次都会 `persist()`，每次要整份 `JSON.stringify` 三遍（pack、comparePut 的两次比较）再算校验和，手机上会明显卡顿。旧卷封存记录在 localStorage 里存完整状态和两份 raw，永不清理。
- **修改**：
  1. IndexedDB 新增 `volumes` store，归档卷以 `runId:from` 为键只追加；槽位主档只保留最近 36 旬和卷目录索引。导出 JSON 时把各卷拼回去，保持导出格式兼容。
  2. 归档章节的 `entries` 按 path 聚合（同 path 同来源合并），去掉 0 增量。
  3. localStorage 恢复副本只存“核心状态”（不含 volumes 和 history 正文）；旧卷封存只写 IndexedDB，最多保留 5 份，超出时提示导出。
  4. 排程类修改 `persist` 去抖 800 ms；`comparePut` 改为比较 `revision + checksum`，不比较整份 JSON。
  5. `talks` 只保留最近 36 旬；`pending.forecast.state` 不再保存 `history` 和 `volumes` 副本（提交时从 base 状态拼回）。
- **验收**：模拟 200 年（含 3 段每段 300 字的模拟正文），槽位主档 < 2 MB，恢复副本 < 1 MB；导出后再导入，逐旬往返一致（沿用 100 旬往返测试，扩大到 1,000 旬）。

### E2　图标占单文件 65%
- `src/ui/icon.js` 有 593 KB（base64），`index.html` 共 910 KB。只保留 32 px favicon、180 px 苹果图标、192 px 清单图标，用 pngquant 压缩或改成 WebP，目标总量 < 60 KB；1024 和 512 尺寸只放在 `docs/`，不进运行包。

### E3　UI 源码可维护性
- `render.js`、`memorials.js`、`style.css`（39 KB 只有 183 行）都有几 KB 长的单行拼接。按逻辑单元拆函数、换行格式化，不改行为；可以用 Stage 9 的 harness 对比格式化前后七条路径的 forecast 哈希。

### E4　零碎问题
- `edicts.js` 中的 `fateModifier` 导入了但没用。`execution()` 的骰面修正是 `(die−10.5)`，DESIGN 是 `(die−10.5)×4`，这是有意偏离还是遗漏？请在 PR 说明里写清楚，二选一。
- `privateAction` 自己另掷一次骰子，和 DESIGN“每旬一次天命骰”不一致；可以改用本旬 `die`（需要从 forecast 传入）。
- `forecastTurn` 中“上朝/批折”没有 `memorials` 时，会默认处置前三本。改成必须显式传入，否则报错。
- `commitTurn` 处理 `factUpdates` 时，先 `includes(fact.reason)` 再做类型判断，顺序要调换。
