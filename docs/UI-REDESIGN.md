# 《御极》界面改版规格 · 夜御案

版本：阶段 9。只改表现层（`src/ui/*`、`style.css`、`src/ui/shell.html`），不改 `src/core`、`src/llm`、`src/store` 的任何逻辑与存档结构。
参考稿：`reference/ui-mock/Main.dc.html`（桌面御案）、`Memorial.dc.html`（批折展开）、`Mobile.dc.html`（手机御案）。这三个文件是设计工具的源码，`<x-dc>`、`<sc-for>`、`{{…}}` 是模板语法，不要照搬；只看其中的内联样式、结构与 `renderVals()` 里的示例数据。

## 1. 设计原则

- 深色案面，浅色纸张：界面底色是深紫檀，凡是"纸"——奏折、正文章节、奏报卡——一律用宣纸色。层级靠"纸在案上"区分，而不是靠更多边框。
- 朱砂稀用：只用于「急」印、主按钮「起驾 / 朱批」、朱批文字、章节编号。其他强调一律用金色。
- 每个数字都要有方向：国势数值显示与上旬相比的涨跌（▲/▼），跌破危险线的标红并给卡片换边框色。
- 行动卡把代价写在卡上：可放的时辰、精力消耗、特殊条件（选秀年、无战事）直接显示，不用点开才知道。

## 3. 字体

用 Google Fonts，构建时以 `<link>` 引入；离线或加载失败时退回系统字体，不影响可用性。

- 标题、数值、正文章节、奏折原文：`Noto Serif SC`（400 / 600 / 900）
- 界面文字、说明、标签：`Noto Sans SC`（400 / 500 / 700）
- 朱批和「急」印：`Ma Shan Zheng`（只用在这两处）

字号：顶栏数值 20，日程槽标题 20，章节标题 26，章节正文 17 / 行高 32，奏折正文 18 / 行高 36，朱批 40，说明 12–13。手机正文 16 / 行高 30。

## 4. 桌面布局（≥1100px，参考 `Main.dc.html`）

```
┌ 顶栏 92px：印章+年号 │ 国势四组卡（钱粮/民政/君威/圣躬）│ 存档 设置 ┐
├ 行动坞 296px ┬ 主区（弹性） ────────────────┬ 奏报匣 340px ┤
│ 朝政 2×2     │ 本旬日程 + 精力圆点「余 6/9」   │ 奏报纸卡 ×N    │
│ 人事 2×2     │ 三槽（朝/午/夜）              │                │
│ 内廷 2×1     │ 预估条 + 「起驾」             │ 宏愿与心事      │
│ 出行 2×1     │ 正文章节（宣纸，占满剩余高度，可滚动）│ 进度条 ×4      │
│ 殿阁 3×2     │                              │                │
└──────────────┴──────────────────────────────┴────────────────┘
```

- 顶栏国势：四组卡片 `flex: 3 / 2 / 2 / 2`。每项：小标签 + 衬线数值 + 单位 + 涨跌，下面 72px 宽、3px 高的进度条。涨跌按「本旬预演前 vs 上旬提交后」的差值计算，没有变化不显示。危险阈值：民心 / 吏治 / 皇威 / 健康 < 40，国库 < 月支出 × 2，心情 < 20。
- 原底部的殿阁栏取消，殿阁入口挪到行动坞底部（3×2 网格）。
- 行动坞分组固定为：朝政（上朝、批折、下旨、任命）、人事（召见、宴请、外交、私下行事）、内廷（后宫、选妃）、出行（出巡、亲征）。每个按钮 52px 高：左侧 28px 字标，右侧名称 + 一行说明（「朝 · 精力 2」「午 · 选秀年」「无战事」）。不可用时降低不透明度，并在说明里写原因。
- 日程三槽：已排 = `--panel-active` 底 + 金色描边，内容为「时辰 · 精力」「行动标题」「一行摘要」；空槽 = 透明底 + 虚线，写「＋ 安排夜间」和可放的行动。槽仍保留拖放功能。
- 预估条：显示预演里能确定的钱粮变化和主要成算（执行度预估），右侧是「起驾」主按钮。没有排程时按钮文字改为「歇息」。
- 精力：9 个圆点，已排的灰色、剩余的金色，旁边写「余 X / 上限」。超支的圆点用 `--down` 色，并在预估条里提示劳累后果。
- 正文章节：宣纸卡，顶部是「第 N 章 · 标题 · 天命」，正文首行缩进 2 字。章节底部显示起居注、风闻、宏愿进展三个小标签，点开后展开明细（替代原来章节里那块灰底说明框）。

## 5. 批折 / 上朝（参考 `Memorial.dc.html`）——这是改动重点

彻底取代现在的表单弹窗（时辰下拉、复选框、统一处置、立场下拉）。

1. 在奏报匣点一本奏报，或者在行动坞点「上朝 / 批折」，打开全屏批折浮层。
2. 顶部是本次处置的奏报队列（上朝最多 3 本，批折不限），用圆角标签显示序号和标题；当前这本高亮。时辰由行动自动决定（上朝 = 朝），只有批折时才在队列右侧给一个「朝 / 午」切换。
3. 左边是展开的奏折（宣纸卡）：「急」印、标题、上奏人和派系、类型、剩余期限、正文（模型写的 `memorial.text`，没有时用引擎的标题与请求兜底）、相关州郡数值。
4. 右边是「御批」：每个引擎选项一张卡片，列出效果包里的每一项（负面用 `--down`，正面用 `--up`，中性用 `--text-soft`）。能预估执行度的选项，在卡片右上角写「执行度预估「敷衍」」。选中的卡片金边。「发部议」「留中」作为普通选项放在同一列。
5. 廷议区：只在上朝且立场为「廷议」时显示，内容为引擎抽出的 2–3 人、赞 / 否 / 中的标签和一句派系理由（数据来自阶段 8 的廷议结果，没有就不显示这一块）。
6. 朱批：选完选项后，可以在奏折右下角写自由朱批（输入框，朱色 `Ma Shan Zheng` 显示，40px，略微倾斜 −4°）。朱批仍走现有的分类逻辑。
7. 「当廷问责」从下拉框改成：在奏折的上奏人名字上加一个「问责」小按钮。
8. 底部按钮：「留中不发」（次要）、「朱批，下一本 ›」（主要）；最后一本时改成「批毕，入日程」。全部批完后把决定写入日程槽，关闭浮层。
9. 键盘：数字键 1–4 选择选项，Enter 下一本，Esc 关闭；焦点要锁在浮层内。

## 6. 其他浮层

召见面谈、宴请、下旨、任命、外交、后宫、选妃都改用同一套外壳：`--desk-shade` 底、左纸右案的双栏结构。纸面一侧显示人物卡或旨意文书，案面一侧放选项和成算。现有表单字段可以保留，但要改用新令牌：输入框用 `--panel` 底和 `--line` 描边，高度 44px，聚焦时描边变金色。下拉框尽量换成分段按钮或卡片选择。

殿阁（朝堂、后宫、天下、内库、宗室、史馆）沿用现有内容，只换配色与字体：深色案面做底，人物卡和州郡格子用宣纸卡。

## 7. 手机（<900px，参考 `Mobile.dc.html`）

- 顶栏：印章、年号、「精力 余 X / Y」、菜单按钮；下面是 4 格国势（国库、民心、吏治、皇威），各带涨跌，危险的标红边。点击国势区域展开完整的四组。
- 三槽竖排，每槽最低 56px；下方是全宽「起驾」按钮（48px 高）。
- 正文章节占满剩余高度，可滚动。
- 底栏四键（64px 高）：行动、奏报（带数量）、殿阁、起居注。点开为上拉抽屉，沿用现有抽屉逻辑。
- 批折浮层在手机上改为单栏：奏折在上，御批选项在下，底部按钮固定。

## 8. 验收

- 1280 / 768 / 390 三种宽度截图，和三张参考稿逐项对照，在 `qa/stage9-*.png` 存档。
- 所有文字对比度 ≥ 4.5:1（大于等于 24px 的文字 ≥ 3:1）；触控目标 ≥ 44px；Lighthouse 可访问性 ≥ 95（对动态浮层另做一次快照审计）。
- 批折流程：上朝 3 本、批折 6 本、发部议、留中、问责、朱批，每条路径都要能走完，并且写入日程的决定和旧界面产生的完全一致（用同一个种子对比预演结果）。
- `npm test` 全部通过，无模型样张模式可以完整演示。
- 不得修改 `src/core`、`src/llm`、`src/store`；如果确实需要新的数据（例如涨跌需要上一旬的快照），只在 `src/ui` 里从现有状态推算。
