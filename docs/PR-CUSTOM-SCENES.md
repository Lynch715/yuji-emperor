# 从日程安排自拟情节，并在原场景接着写

玩家原本只能用御前面谈和政令表达意图，缺少安排一段具体经历的入口。新增朝、午、夜均可使用的“自拟情节”：选现有人物、填写地点和梗概，起驾后展开；当前章的每场情节都有“接着写”。成败继续由现有自由度和纯函数裁决，模型负责具体动作、对白与反应。

## 使用与规则

每场精力1，可多选人物或独处，地点选填，梗概和后续想法最多8000字。日程显示所选人物与地点，点已排情节可修改。没有新建自由度字段，沿用 `settings.freedom` 与现有 `adjudicate()`。

有处死、任免、战争、拨款、赏罚等实质动作时采用已有意图裁决，避免整体再掷一次；纯叙事目标才按已有能力、人物权谋/性格和关系计算基础检定，套用三档成功率。一般档先提升完整成功，再把剩余失败的一半转成带代价的部分成功。不同动作结果分别传入剧情，未办成的不能写成已办成。

单纯“接着写”继承结果，不再掷骰、耗精力或推进日期；新的愿望才判定。场内重复提到已办动作不会再支付或生效，明确追加才另办，并向叙事标明复用事项。续写与原章共用A9好感额度，包括原章模型反应；违规句先改写、再校验、最后删句，与原章共用最多一次改写标记。A1–A14、成人侍寝条件和孕产系统来源保留。

## 事务与存档

`core/scenes.js` 负责情节检查、裁决、独立续写预演与提交。仍使用现有 `pending.forecast`，以可选 `pending.kind=scene` 分支，不增加第二套待续槽或档位。模型请求前保存结果，关闭窗口中断请求也保留预演；刷新、失败重试复用原请求、原骰、实际代价。检查runId、回合、revision、RNG指纹和目标章，receipt保证同一续写只提交一次。简写同样提交原结果，不进入下一旬；实际开始下一旬面谈或正式提交下一旬后，旧场只读。

存档升v18，`scene-schema.js` 校验新增的可选章节场景、步骤、裁决、防重复凭据及改写标记。旧档缺失新字段即无自拟情节，旧待续不重算。分卷沿用原压缩与存储结构，JSON及起居注Markdown保留各段。已验证的经历进入既有长期事实窗口，供后续剧情参考。

浏览器实测发现原恢复副本省略全部章节，会使新场景缺少续写所需上下文；现仅在最新章有自拟情节时保留这一章，普通旧副本仍省略正文。补充了真实双通道保存、仅靠恢复副本恢复、原骰重试测试；损坏副本和冲突仍进入原只读保护，不自动覆盖。

## 相对原方案的实现选择

精力默认每场1；纯续写沿用结果，明确新尝试才判定。摄政可进行日常场景，实际政令仍受原限制；亲征时沿用既有京中行动约束。新存档字段都可选，恢复副本仅保留当前章，这是保证续写可恢复所需的结构扩展。以上均已同步DESIGN.md，无需玩家另选档位。
