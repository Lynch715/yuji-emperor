# 自由度与剧情断言改造

按用户指定顺序分三次提交：第三步误判修复 → 第一步先裁决再叙事 → 第二步概率与门槛。以本次用户方案替代 DESIGN 中原“传奇 / 写实、自由执行度 +30”的口径；未新建第二套档位字段，保留 `settings.freedom = free / mid / real`，界面显示“随心所欲 / 一般 / 严格”。

## 裁决与叙事

- 自由圣旨、逐本朱批和面谈发言先请求仅含 JSON 的意图列表。未知人物、外邦、动作及孕产请求降为 other；所有人物、外邦、官职 ID 经当前存档名册核对。试读使用保守的本地解析器。
- 引擎执行 kill、appoint / dismiss / promote / imprison、war、allocate、favor、decree。资源、余额、容量、单旬好感上限仍由 core 截断；结果注明实际数量。征兵沿用现有征兵费用，人数取整数，面谈征兵的国库支出也占用拨款额度；同一来源调回原处按零处理。
- 成功及部分成功改变真实状态，并产生与系统事件同等的事实；模型收到实际结果后才写正文或对白。死亡官员保留历史对象，移出在世名册。
- 决定存于 `intentResults`、面谈和章节。存档升 v11，旧档补空记录，缺省档位仍为 mid；旧 pending 原结果、原骰不重算。续写重试只复用已经保存的预演，原提交幂等、过期保护和结构断言不变。

## 概率与门槛配置

配置唯一入口：`src/core/freedom.js`。先保留原规则的基础判定，再对失败以 k 的概率转为完整成功，等价于 `p+(1-p)×k`。一般档仍失败时再判一次，50% 改为有代价的部分成功。用户已确认两次判定口径：p=20% 时完整成功60%、部分成功20%、失败20%。

部分成功三种代价的配置为：国库额外支出1万两、相关大臣好感−3、民心效果包−0.5（沿用全国效果0.3系数，实际约−0.15）。找不到可扣好感的相关大臣时改为民心，民心已为零时改为国库支出；余额不足按既有欠款规则记入欠款。不会随便扣无关大臣的好感。

## 断言修复与边界

- A8 仅改写与本旬事务、负责官员或衙门同句的执行词，不改“内侍照办，送来了茶”。
- A12 对承诺词前后五字内的否定 / 反问豁免，保留“臣再尽力也办不到”；失败的结构化面谈仍检查虚假承诺。
- A1 死亡词绑定同句中的实际主体 / 对象，排除“死去的念头”等搭配；甲下令处死乙，不能拿甲的死亡事实给乙放行。
- A7 年龄 / 兵力按同句最近人物或军队核对；征兵的真实增量也可作为对应军队的依据。单位表补石、斛、亩、顷、成、%、户、匹，支持万、亿及中阿数字混写。
- 石与斛各取同单位证据，不擅自假定朝代换算；顷按100亩、成按10%核对。无依据的“户部调走九百九十九万石粮食”会被拦下。

可选第四步暂不实施：继续保留既有删句、A8 替词及 A14 含蓄化回退，避免本次另加一轮付费改写与失败重试路径。不是放宽断言。
